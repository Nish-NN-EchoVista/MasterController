MasterController software architecture

One laptop UART in, six DataController UARTs out, twelve EVS2 boards behind them. The MasterController is a pass-through line router. It forwards commands down, merges and renumbers telemetry coming back up, and never joins, splits or silently drops a line.

  • STM32H7A3 · 280 MHz
  • 7 routed UARTs + ST-LINK VCP
  • 921 600 baud up · 57 600 baud down
  • @1…@12 EVS2 addressing
  • 346 host test checks
  • v1.0.0 · main
01

System overview

The F401 DataController already routes @1/@2 commands to its two EVS2 boards and tags their replies [ESV2-1]/[ESV2-2]. The MasterController repeats that pattern one level up, for six DataControllers. The DataController firmware is unchanged: each one sees exactly the text a laptop would send it today.

Does

Routes whole lines

Sends @n commands to one board, #k commands to one DataController, and plain commands to all six. It also merges and renumbers the replies.

Guarantees

Atomic behavior

No line is ever split or merged. A broadcast reaches all six DataControllers or none. A stop overtakes queued traffic.

Does not

Own any process logic

No pump, defog or sequence behavior. Binary protocol frames are dropped in v1 and never forwarded.

03

Software layers

The code is split so that everything that decides what happens to a line has no hardware dependency. It is plain C that compiles and runs on a PC against a fake platform. Only one file knows about DMA streams, UART registers and the watchdog.

Listed top to bottom from the hardware inward. Each layer only calls the one beneath it.

CubeMX-generated

main.c · stm32h7xx_it.c · hal_msp.c

Clock, power, GPIO, UART and DMA initialisation, generated from MasterController.ioc. The only hand edits sit inside USER CODE blocks, so regenerating is safe:

  • mc_board_init() before the loop and mc_board_poll() inside it;
  • mc_board_fatal() in Error_Handler and the fault vectors.

04

Execution model

There is no RTOS and there are no queues inside interrupts. DMA moves received bytes into memory with no CPU involvement. Interrupts refill the transmit FIFO and set one flag when a line has finished sending. Every decision is made in a single main loop, so no queue is ever touched from two contexts and nothing needs locking.

Main loop mc_board_poll(), runs continuously

  1. Measure the time since the last pass. A gap long enough to fill a receive ring is recorded as a possible overrun.
  2. For every port, count and clear the framing, noise and parity flags, and restart the RX DMA if its stream or DMAR bit has stopped.
  3. mc_app_poll(): receive and route laptop lines, then receive and retag DataController lines (at most 4 KB per port per pass).
  4. Health checks: DataController online/offline changes, congestion reports, line-error warnings, and a pending status request.
  5. Transmit for each of the 8 ports: retire a finished line, abort a stalled one, and start the next whole line.
  6. Update the LEDs, refresh the watchdog (only here), and record the worst loop time.

Interrupt & DMA context minimal by design

  • RX DMA: circular, byte-wide and interrupt-free. The main loop reads the DMA counter to find new data.
  • UART IRQ: the HAL TX routine refills the FIFO 8 bytes at a time. Error interrupts are deliberately left off, so a framing error can never abort reception.
  • TX complete: HAL_UART_TxCpltCallback clears the port's busy flag, and nothing else.
  • Button: the EXTI callback sets a flag that requests a status report.
  • Faults: HardFault, MemManage, BusFault, UsageFault, NMI and Error_Handler record a reason code, then reset the board.
05

Laptop → boards

A command moves through seven stages from the laptop's UART to the DataController wires. Each stage either passes a complete line on, or stops it and replies with an [MC] E: message. Nothing is ever partly sent.

Admission, in two rules

Ordinary lines

All-or-nothing

Every target queue is checked before any copy is made. A broadcast needs space in all six, and each queue always keeps back its 4 reserved slots. If any one is full, no DataController receives the line, and the laptop gets one clear busy reply.

stop · cancel · @0 stop_all

Purge, then jump the queue

Unsent ordinary lines for the same boards are discarded and the count is reported. The stop is then placed right behind the line currently on the wire, and behind any earlier stops. It can use the reserved slots.

06

Boards → laptop

Six independent streams are merged into one. Each DataController has its own ring buffer and line builder, so a slow or noisy link can't damage another's lines. Each finished line is renumbered and queued as one unit on the laptop link.

08

Whole-line queues

Each queue (mc_txq) is a pool of fixed 522-byte slots, and each slot holds exactly one complete line. The UART only ever sends one whole slot at a time. Reordering or purging the queue therefore can't produce half a line, because a partial line never exists in a queue.

Example DataController queue, send order left to right.

  • Locked head: the line currently being sent can never be moved or purged.
  • Front insert: push_front is used only for the CRLF that ends an aborted line. It goes ahead of everything, including waiting stops.
  • Urgent lines: they go after the head and after earlier urgent lines, so stops keep the order they were sent in. Urgent lines are never purged, so a later stop can't erase an earlier one.
  • Purge: removes only ordinary lines whose board tag overlaps the stop's target, and reports how many.
  • Reserve: ordinary traffic may only use a queue while more than 4 slots are free, so a stop always has room.

10

Integrity & recovery

A command router is only safe if damaged or interrupted input can never become a different valid command. For example, a lost letter can turn start_sweep into tart_sweep, and a lost line ending can merge two commands into one. These are the defenses, strongest guarantees first.

UART errors on the laptop link

The UART drops any byte received with a framing or noise error, and its flag only says that an error happened, not where. So when the flag changes, the MasterController notes how much data has arrived up to that moment, including bytes still waiting in the ring buffer. Every line holding a byte from before that point is discarded, however much input was buffered.

Design decision: the ST HAL's interrupt handler aborts DMA reception on the first framing error, so it's never given UART error interrupts. The CubeMX setting "DMA disable on RX error" is also turned off at runtime (CR3.DDRE cleared, and OVRDIS set so an overrun can't block reception). Reception keeps running, and errors become counters instead of outages.

12

Verification

Because the platform contract is so small, the same application code runs in three places: on the board, against a scripted fake, and inside a real-time simulator.

tests/host · C

Unit & app tests

346 checks. test_core covers the queue, line builder and router. test_app covers the full application against the fake, with injected stalls, UART errors, DMA restarts, overruns and congestion. Built with -Werror -Wconversion.

tests/host · mc_sim

Simulator

The real core behind a TCP socket, with DataController ports looped back and wire time emulated at each port's baud rate. It speaks to pyserial as socket://localhost:5555.

tools · Python

Loopback commissioning

With TX-to-RX jumpers on each DataController port, it checks every route, broadcast atomicity, burst ordering and stop behavior, and requires a complete status report with every loss counter at zero. A self-test confirms it fails when the report is bad.

The firmware builds headless in STM32CubeIDE with 0 errors and 0 warnings in both Debug and Release. The mc_*.c sources also compile cleanly with -Wextra -Wconversion -Wshadow -Wformat=2 for Cortex-M7. Hardware still needs validating before relying on it: electrical checks, clock accuracy, real UART and DMA faults, and the attached F401 and EVS2 boards.
